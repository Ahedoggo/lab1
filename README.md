# Практическая работа №1, вариант 2

Локальный lakehouse, собранный из MinIO, Lakekeeper и Trino: три слоя медальона на данных
TPC-H `sf1` и оценка того, насколько формат файлов и кодек сказываются на объёме данных
и длительности запроса.

## Запуск

Команды следует выполнять, находясь в корневой директории проекта. При самом первом запуске
скачиваются образы, из-за чего он идёт существенно дольше, чем все последующие.

```powershell
docker compose up -d postgres minio lakekeeper trino
python scripts/setup.py
python scripts/run_lab.py --scale sf1 --repeats 5
docker compose up -d --build bi
python scripts/check_bi.py
python scripts/report.py
```

Понадобятся Docker с поддержкой Compose и Python версии 3.11 или новее; сторонние библиотеки
ставить не нужно, так как скрипты обходятся стандартной библиотекой. Оперативной памяти всему
стеку хватает около 8 ГБ: JVM Trino ограничена 3 ГБ, а на один запрос отведён 1 ГБ.

Дашборд доступен по http://localhost:18088 и не требует авторизации.
Помимо него работают:
Trino (http://localhost:18080, пользователь `lab`)
Lakekeeper (http://localhost:18181)
консоль MinIO (http://localhost:19001, `labadmin` / `lab_local_password`)

## Результаты

- [Отчёт по работе](отчёт.md) — формируется скриптом `scripts/report.py` на базе файлов, лежащих в `results/`.
- [Топ-20 клиентов](results/gold_top20.csv) — итоговая витрина слоя Gold.
- [Бенчмарк](results/benchmark.csv) — сопоставление форматов файлов и кодеков.

## Содержимое

- `compose.yaml`, `config/` — описание стека и параметры Trino: каталоги, память, таймауты.
- `scripts/setup.py` — создаёт бакет и регистрирует warehouse в Lakekeeper.
- `scripts/run_lab.py` — главный конвейер: загрузка TPC-H в четырёх вариантах Bronze,
  сборка Silver и Gold, замеры, сверка с эталонным Q10, проверки качества,
  показ эволюции схемы и отката к снимку.
- `scripts/report.py` — готовит отчёт; если измерений нет или они неполные,
  завершается ошибкой, а не подставляет примерные значения.
- `scripts/check_bi.py`, `scripts/screenshot.py` — проверка дашборда посредством Streamlit AppTest
  и необязательные снимки экрана в настоящем браузере (потребуются установленный Edge и `pip install websockets`).
- `sql/` — SQL реально выполнявшегося запуска, отдельный файл на каждом шаге.
- `results/` — измеренные CSV/JSON, журнал запросов с query ID и снимки экрана.
- `bi/` — Dockerfile, зависимости и исходный код дашборда.
